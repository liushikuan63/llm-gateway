# VibeCoding 任务卡 · 路由韧性与模型级管控

> 背景文档：网关把「上游挂了怎么办」和「用户想钉死哪个模型」两件事都塞进了
> 自动路由，导致 2026-10-05 出现「DSH 报 API 密钥无效，但密钥其实没问题」的现象。
> 本文是那次的根因记录 + 由此拆出的四张卡。

---

## 一、根因（2026-10-05 实测，不是推演）

DSH 一轮失败，显示 `AUTH / API 密钥无效`，模型选择器是「网关自动分流」。
网关审计 `requests.id=72`：

```text
model=auto  status=401  error=auth_failed  fallback_attempts=0  routed_provider=NULL
- agentrouter/claude-opus-4-8  status=401  retryable=False  7828ms
    {"error":{"message":"unauthorized client detected, contact support ..."}}
```

因果链：

1. 本地 ollama（priority=10，本该第一个命中）当时不可用；
2. 候选链落到 priority=100 的一批，第一家是 `agentrouter`；
3. agentrouter 对 401 返回 `retryable=false`（`failover.rs::is_fatal_auth`
   把 401/403 定义为「要人来换 Key」）；
4. 网关**当场终止整条链**，`fallback_attempts=0`，健康的 commandcode /
   openrouter / sensenova / maas-api 一个都没被试；
5. 网关把 401 回给 DSH → 显示成「API 密钥无效」，**指向客户端而不是真正原因**。

两个容易走错的方向都已排除：

- **不是密钥不一致**：DSH 的 `LLMGW_API_KEY` 与网关 `unified_key` 的 SHA256 相同，
  审计里 `client=local-unified-key` 说明入站鉴权是通过的。
- **不是模型失效**：agentrouter 的模型在上游目录里都活着，只是这把 Key 被拒。
  这是**供应商级凭据/额度**问题，不是模型级 404。

配置层的止血已落地（凭据被拒的供应商整家 `enabled=0`），修后
`auto` 恢复 200；只存在于已停用供应商的模型在 **1~33ms** 内 404（根本没发出上游请求）。
但**行为层仍然脆弱**：只要「启用中」的供应商密钥失效，同一个坑还会再踩一次。

## 二、【R1】鉴权失败策略：确认 → 跳链 → 自动停用

**目标**：上游 401/403 不再当场终止整条候选链。

**语义（用户 2026-10-05 定）**

```text
一次 401/403
   → 复测 confirm_retries 次（默认 1，复用**同一个请求**，不是另造探针）
       ├─ 复测通过          → 当成成功结果继续用它（承认「这次能用」）
       └─ 复测仍 401/403    → 判定真实不可用
              ├─ 跳到下一家继续（只跳带 Key 的候选，**不回落到免 Key 后端**）
              └─ 按模式把该供应商自动停用，写明原因
   复测给出的是限流等其它错误 → 不足以判定凭据失效，按普通可重试失败处理
```

**为什么要有复测**：中转站的 401 未必等于「Key 永久失效」——可能是某条路径被风控或
瞬时拒流。不复测就判死，会把**仍然可用**的供应商踢出路由；而复测用**同一个请求**，
是因为探针成功只能证明「探针能过」，证明不了「这个请求能过」。

**配置**（`config.toml`，`[auth_failure]`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `mode` | `skip_and_disable` | `strict` 维持旧行为（一次 401 终止）/ `skip` 只跳过 / `skip_and_disable` 跳过并自动停用 |
| `confirm_retries` | `1` | 判定前的独立复测次数，上限 3（再多只是放大延迟） |
| `exempt_providers` | `[]` | 豁免名单：这些供应商永不被自动停用 |

**「用户选定」豁免**（用户要求「可以强制走用户选定的」）：
主用供应商（界面上的「设为主用」）与 `exempt_providers` 里的供应商都不自动停用。
自动停用会**追加**写进 `providers.note`（不覆盖用户自己写的备注），
并同步刷新路由表，让它立刻退出候选链。

**判据**
1. 401 + 复测通过 → 同一候选返回 200，`attempts` 里能看到那次「确认复测」；
2. 401 + 复测仍 401 → 跳过第一家，命中第二家，`fallback_attempts >= 1`；
   **对照组**：把 `mode` 设成 `strict` 时必须立刻终止且 `fallback_attempts == 0`
   （只写前一条的话，测试可能只是因为根本没走到新分支）；
3. 候选链里**只剩免 Key 后端**（本地 ollama）时，鉴权失败**不得回落到它**；
4. 主用供应商 / 豁免名单里的供应商：复测确认失败后**仍然可用**（断言 `enabled` 未变）；
5. 自动停用后 `/v1/models` 不再出现该供应商的模型，且 `note` 里有原因；
6. `confirm_retries = 0` 时行为等同「第一次失败即确认」，必须也有用例。

## 三、【R2】单模型禁用

**状态：另一批工作已在并行实现**（2026-10-05 15:5x 起，工作区未提交）。
其做法与本卡一致：`ModelRef` 补 `enabled` 字段 → `repo` 读写 `models.enabled` 列。
该列 2026-10-05 之前就存在，`list_models_of` 一直在 `WHERE enabled = 1` 过滤，
缺的是领域字段与写入，所以「禁用模型」此前只能手改数据库、且撑不过一次保存。

**本卡剩余工作（避免重复劳动）**

1. **验证连接完整性**：`upsert_provider` 整体替换 models 时，被禁用的模型
   仍会以 `enabled=1` 回来——除非禁用状态被持久化。需要一条**回归用例**：
   禁用某模型 → 保存该供应商 → 禁用状态仍在。
2. 命令与界面接线（见 R4）。
3. 停用/启用后路由立即生效（`gateway.reload_providers()`）。

**判据**：禁用后该模型不出现在 `/v1/models`；直接请求它返回「模型未找到」；
保存供应商后仍被禁用；**对照组**：未禁用的同名模型不受影响。

## 四、【R3】模型级「不自动切换」

**目标**：某些模型必须**只走它自己**。失败就如实报错，不许悄悄换一个模型顶替。

**为什么需要**：有些模型对调用方有不可替代的语义（比如固定上下文窗口、固定输出格式、
模型 id 本身就是业务标识）。自动降级到另一个模型，调用方拿到的是**看起来成功、
实际换了模型**的结果——比失败更难排查。

**数据**：`models` 表加一列 `pinned INTEGER NOT NULL DEFAULT 0`（可重入 `ALTER TABLE`，
沿用 `db/migrations.rs` 既有风格）。`ModelRef` 加 `pinned: bool`，默认 `false`，
保证旧配置与旧载荷反序列化后行为逐位不变。

**语义**（写在 `router::candidates` 之后、`FailoverChain` 之前）

```text
候选链里出现 pinned 模型
   → 只保留它一个候选
   → 失败即返回该错误，不降级、不回落
   → 审计里 fallback_attempts = 0，且要能区分「被 pin 住所以没试第二家」
       与「试了但都失败」
```

**判据**
1. `pinned` 模型失败 → 返回原始错误，`attempts` 记录只有 1 条，
   且**上游只被调用 1 次**（用计数 mock 断言调用次数，不能只看错误码）；
2. **对照组**：同一个模型 `pinned=false` → 必须发生降级，调用次数 ≥ 2；
3. 虚拟模型（`auto` / `fastest` / `smartest`）命中 pinned 模型时，
   仍以 pinned 为准——否则「钉死」会被虚拟模型绕过；
4. 多个 provider 上同名模型、其中一个 pinned → 只有 pinned 那个进入候选；
5. 停用 pinned 模型后，路由退回普通降级行为（pin 与 disable 的优先级明确）。

**明确不做**：不提供「把整条链锁死到某个 provider」的全局开关。
那是 `set_active_provider`（主用供应商）已有的能力，两套机制职责不同：
主用是「默认先走谁」，pin 是「这个模型不许被替换」。

## 五、【R4】界面与设置接线

1. 设置页新增 `[auth_failure]` 三项（模式 / 复测次数 / 豁免名单）；

   且新控件要加进 `scripts/ui-smoke.cjs` 的 IPC 夹具（否则真环境白屏、测试全绿）。

## 六、判据之外的红线

- 不为了「看起来能跑」而回落到**免 Key** 后端（既有约束，R1 判据 3 守着）；
- 自动停用只影响**供应商**，不动用户的 Key 与备注；
- pin 与 disable 互不覆盖：pin 一个已禁用的模型没有意义，界面要能看出这个组合。
