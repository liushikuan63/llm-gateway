# 0.2.0 验证记录

验证日期：2026-09-12。本文记录 0.2.0 在费用统计、定价自动化、多模态路由与 CLI 工具管理上的实现与实测边界。[0.1.1 验证记录](0.1.1验证记录.md)保留界面、模型目录、客户端备份、托盘与额度查询的上一阶段结果，不作为本版本的校验依据。

## 本轮变化

**费用与定价**

- 模型价格改为整包存储（`models.price_json`），支持输入长度分档价与币种；目录提供的分档价随模型保留并在长上下文请求中生效。
- 价格来源区分「手工定价 / 目录定价」：手工填写的价格永不被自动刷新覆盖；未编辑的目录价保持可刷新。
- 新增「刷新定价」：从公开定价源（默认 OpenRouter `models` 目录，可用 `catalog_feed_url` 指向同结构来源）匿名拉取最新单价，逐项报告更新、跳过（手工价）与未匹配数量。厂商直连的 Provider 只接受完整模型 ID 精确匹配，避免把中转目录价格套用到官方账户。
- 新增时段价（峰谷价/忙闲价）：按 UTC 起止分钟与输入/输出倍率配置，支持跨午夜；每次请求按实际时刻计价，并把命中的档位说明写入审计（`requests.rate_label`）。
- 新增 Token 计数校准：请求成功后按 provider+model 累积「上游实际 prompt token / 本地估算」的 EWMA 比值（`token_calibration` 表，比值截断在 0.5–3.0）；会话记录最近比值（`sessions.token_ratio`）。候选窗口判断按候选比值保守换算，自动压缩阈值按会话比值换算。「用量与审计」页展示样本与比值，支持重置。
- 未配置价格的请求继续显示「未计价」，不折算为 0；花费明确说明是本地估算而非厂商账单。

**多模态**

- 模型级新增 `supports_audio` / `supports_video`（与既有 `supports_vision` 并列），可在模型卡片里勾选；目录的输入模态字段（image/audio/video）会自动带出并支持筛选。
- 请求按内容生成硬约束：含图片/音频/视频的上下文只进入勾选了对应能力的候选；没有任何候选满足时返回 `model_capability_unavailable`（HTTP 400）并说明缺哪种能力。
- 新增协议承载判断，避免"模型支持但链路不支持"造成的静默丢弃：Gemini 原生只接受 base64（`data:`）图片与音频，以及 YouTube / Google 存储视频或 base64 视频；远程图片地址会被明确拒绝并给出原因。Anthropic 链路对音频/视频同样直接拒绝。
- 修复 Gemini 上游丢图：`data:` 图片与音频转 `inline_data`，YouTube / GCS 视频转 `file_data`，此前这些内容会被静默丢弃。
- 上下文 token 估算把音频计入（不再按 base64 字符数计算），图片/视频按保守固定值计入。

**CLI 工具**

- 新增 `cli_tools` 模块与「设置 → 本机 CLI 工具」卡片：检测 Claude Code / Codex / Gemini CLI 的可执行文件路径与版本（PATH + npm 全局目录 + 原生安装目录；Windows 处理 `.cmd/.bat` 并隐藏控制台窗口），查询 npm registry 最新版本并提示可更新项。
- 更新前展示将执行的确切命令（`npm install -g <package>@latest`），确认后执行并回显输出；未安装 npm 时明确提示改用官方安装方式。命令与参数全部来自内置常量，不接受用户输入。
- 新增「运行连通性自检」：检查 `/healthz`，并用统一 Key 发一次最小请求（约 1 个 token），确认端到端可用并显示实际路由到的上游。

真机验证发现并修复了两个缺陷（均为自动化测试未覆盖的路径）：

1. **会话列表在新增列后漏改 SELECT**：`commands::list_sessions` 自己写 SQL，新增 `sessions.token_ratio` 后只改了读取没改查询，启动即 panic。由于 `Cargo.toml` 设了 `panic = "abort"`，一个后台 worker 崩溃会直接结束整个应用——真机上表现为「双击图标没有任何窗口」。现已把该查询收敛到 `repo::list_sessions_with_counts`，并在 `tests/db.rs` 增加真实数据库回归用例；该用例在缺列时能复现同样的 `ColumnNotFound("token_ratio")` 失败。
2. **「检测本机 CLI」与标签不符**：该按钮原本也会联网查询 npm 最新版本，与按钮文案和函数注释不一致（与另一个按钮只差代理设置）。现改为纯本机检测不联网，只有「检测并检查更新」才查 registry，界面说明同步写明。

验证结束后已清理：停止应用与 mock 进程，用界面删除测试供应商，并从本机数据库移除本轮产生的请求/日聚合/校准/会话记录（`providers` 0、`models` 0、`requests` 0、`usage_daily` 0、`token_calibration` 0、`sessions` 0、`session_messages` 0、`meta` 空）。

## 后续完善（2026-09-12 第二轮）

在版本号保持 0.2.0 的前提下完成四项完善：应用标识替换、界面排版对齐修复、CLI 工具管理扩展（3 → 21 个并新增下载安装）、手册同步。上一节及以前的内容保持原样，本节为最新状态。

### 变更

**应用标识**

- 新增 `src-tauri/icons/logo.svg`（三条上游汇聚为单一出口，对应「一个网址 + 一个 Key」）与 `scripts/generate-icons.mjs`（`npm run icons`：Playwright 渲染 SVG → 全套 PNG + 16/24/32/48/64/128/256 多尺寸 ICO），替换应用图标与托盘图标；侧栏品牌区改用同一矢量的 `LogoMark` 组件。

**界面排版对齐**

- 根因：全局 `button` 未设置 `display`（浏览器默认 `inline-block`），图标与文字按基线对齐——实测图标中心比文字中心高 3px。修复为 `inline-flex + align-items: center + gap`，并让 `button > svg` 不参与伸缩；表格单元格与 `.tag` 增加中线对齐。

**CLI 工具管理扩展**

- 清单从 3 个扩展到 21 个：新增 Qoder CLI 国内版、Cline、Amp、Auggie、Continue CLI、Crush、Factory Droid、iFlow CLI，以及此前的 OpenCode、OpenClaw、Pi、DeepSeek Harness、WorkBuddy、Grok Build、Cursor CLI、TRAE CLI、Hermes Agent。
- 安装来源分两类（`InstallSource`）：npm 全局安装（17 个）与官方 PowerShell 安装脚本（4 个，命令为厂商文档原文，仅 Windows 可用）。
- 新增下载安装：未安装的工具同样查询 npm 最新版本并显示「将安装的版本」，可直接一键安装；命令 `update_cli_tool` 泛化为 `install_cli_tool`。
- 逻辑自洽：按钮按状态呈现「安装 / 更新 / 重新安装」，每个按钮都会把工具装到最新版；缺少前置条件（无 npm / 无 PowerShell）时禁用并在表格上方说明原因。
- 新增工具的包来源均经 npm 元数据核对为官方维护者发布（Amp 为改名后的 `@ampcode/cli`；Goose 因没有可核实的一键安装来源未加入）。

**手册**

- 使用手册新增「安装与更新本机 AI 编码 CLI」一章（共 15 章），`docs/使用手册.md` / `.html` 重新生成；README 同步。
