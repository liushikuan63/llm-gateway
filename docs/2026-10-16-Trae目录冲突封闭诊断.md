# Trae 目录 selector 冲突封闭诊断

本阶段沿 R5 继续。此前两次明确授权的 Trae CN 原生目录只读均返回 `native_catalog_selector_conflict`，授权已消费且没有自动重试；本阶段不发起新的真实目录、登录、刷新、设备登记、领取或模型请求。

本次在 `src-tauri/src/proxy/trae/catalog.rs` 与 `catalog/diagnostic.rs` 增加了封闭诊断分支。selector 冲突仍返回原来的静态错误码，只额外输出一个固定 schema 的 `native_catalog_selector_conflict_v1` 事件。事件只包含版本、固定原因枚举和固定视图字段枚举：`display_name`、token 限额、声明能力、思考选项、协议载体及证据状态等；不保留或输出 selector、配置名、显示名、原始 JSON、值、哈希、长度、URL、账号、设备或凭据。

固定原因包括前一项不可选、当前项被排除、当前项结构无效和已验证视图字段不一致。结构无效的后来项不会再额外输出 shape 诊断，仍保持 selector 冲突的错误优先级。成功目录、完全相同重复项、等价投影重复项、其它错误码和既有 shape 诊断保持原行为。

验证结果：新增诊断 RED 先以退出码 1 证明旧实现没有冲突事件；最小实现后目标诊断通过。Trae 目录诊断回归 **16/0/0**，Trae 目录基础回归 **13/0/0**；完整 Rust lib 回归 **937/0/0**；`cargo clippy --all-targets -- -D warnings` 退出 0，`cargo fmt -- --check` 退出 0，`git diff --check` 退出 0。三个生产文件的旧字节分别保存在本阶段 `before/`，本阶段没有新增依赖、数据库字段、路由权重或前端行为。

本阶段已构建并静默安装新诊断包：NSIS 和 MSI 管理提取均退出 0，各 26 项资源核对通过；安装目录由旧费用排序包备份恢复。安装版免费原生验收使用独立合成资料和拒绝转发 loopback proxy，5 项检查、5 张截图通过，0 次模型、登录或领取请求，真实目录 audience 仍未验证。证据见本阶段 `implementation-proof.json`、`install-diagnostic-state.json` 和 `installed-generic-acceptance-v1/proof.json`。

随后补充了 artifact-only capture/parser：只接受 `native_catalog_selector_conflict_v1` 的固定版本、原因和字段顺序，拒绝额外键、未知字段、重复/乱序字段、原始值、换行和未知版本。纯测试 **5/0/0**，没有启动应用、读取数据库或发送请求；这一步只为未来安全读取诊断日志，不能改变已消费授权的单次约束。

下一步仍需独立复审新包和封闭诊断证据；只有在新的包、绑定和复审完成后，若确有必要，才能取得新的单次 Trae 目录授权。诊断能解释失败类别不代表真实目录或模型调用已成功；此前授权已消费且不能重试。
