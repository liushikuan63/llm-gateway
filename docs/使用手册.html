第一次使用：完成一条可用请求

初次启动且尚未配置供应商时，会出现使用引导。可以逐步阅读、跳过，或通过顶部的使用帮助再次打开。引导不会自动导入示例密钥，也不会替你改写客户端配置。

分清两种 Key：供应商 Key 用于网关调用上游；本地统一 Key 用于你的客户端访问网关。给 Codex、Claude Code 或其他客户端填写的是本地统一 Key。

  1. 打开供应商，点击添加供应商，填写协议、API 地址和供应商 Key。
  2. 获取支持模型，勾选需要的模型，检查上下文长度后保存。
  3. 点击供应商卡片中的测试连接，确认至少一个模型能响应。
  4. 打开设置，复制本地统一 Key；根据客户端选择手动接入或备份并写入配置。
  5. 从客户端发送一个简短问题，在用量与审计中查看实际模型和请求结果。
  • 获取模型目录和查询额度只读；测试连接和实际聊天会调用模型，可能消耗上游额度。
  • 看到模型名称只代表目录可见，不代表当前 Key 一定有调用权限或免费余额。

安装、启动与退出

Windows 安装包提供 NSIS .exe 和 MSI 两种格式，按自己的部署方式选择其中一种。安装后打开 LLM Gateway，默认本地地址是 http://127.0.0.1:15721。

窗口关闭按钮会隐藏界面并继续提供网关服务。需要真正退出时，使用系统托盘中的退出菜单。托盘左键用于恢复主窗口，右键打开控制面板或退出。

  1. 运行与系统匹配的 x64 安装包并完成安装。缺少 WebView2 时，安装程序需要联网安装运行时。
  2. 启动应用后按首次引导配置。供应商、会话、用量与审计、设置是四个主要页面。
  3. 可在顶部切换浅色或深色主题；主题与上次页面仅保存为本机界面偏好。
  • 当前安装包未签名。安装包 SHA-256 和实际验收范围见仓库 docs/0.1.1验证记录.md。
  • 改动监听地址或端口后，需要退出整个网关进程再启动，仅关闭窗口不会重启服务。

添加供应商与获取模型

在供应商页面点击添加供应商。预设会填入常见协议、地址和参考模型名称；仍需提供自己的 Key，并核实服务实际支持的模型。

OpenAI 兼容、Anthropic、Ollama 可以填写基础地址或常见完整聊天接口地址。Gemini 请填写 API 根地址或模型目录地址，例如 https://generativelanguage.googleapis.com/v1beta，不能直接粘贴带模型名的 :generateContent 调用 URL。

  1. 填写供应商名称、协议、API 地址和 Key。OpenRouter 示例地址为 https://openrouter.ai/api/v1；SenseNova 示例地址为 https://token.sensenova.cn/v1。
  2. 点击获取支持模型，按名称、免费价格、工具调用或视觉能力筛选。
  3. 勾选所需模型并添加到配置，确认每个对外别名、上游模型名和上下文长度。
  4. 保存后测试连接；目录获取失败时，可根据官网资料手动添加模型。
  5. 在模型卡片里按官方说明勾选「图像输入 / 音频输入 / 视频输入」；带这类内容的请求只会路由到勾选了对应能力的模型，不会发给纯文本模型。
  6. 同一个区域可以填写输入/输出价格与币种（单位为每 100 万 token）。目录提供价格时自动带出，并标注为「目录定价」；你手动改过的价格会变成「手工定价」，刷新时不会被覆盖。
  • 编辑同一个供应商时，Key 留空可复用已保存密钥。改变 API 地址或协议后，需要重新填写 Key。
  • 复制配置不会复制密钥，副本默认停用。免费筛选只依据上游明确提供的价格，不把未知价格视作免费。
  • Ollama 通过 /api/tags 和 /api/show 获取模型信息；API 是否需要 Key 由本地服务部署决定。
  • 目录若提供输入长度分档价，会随模型保留并自动生效；峰谷价/忙闲价在「峰谷价 / 忙闲价」里按 UTC 时段配置（倍率填百分比，50 表示五折，起点晚于终点表示跨午夜，例如 16:30 → 00:30）。
  • Gemini 原生接口只接受 base64（data:）图片与音频、以及 YouTube / Google 存储视频。若客户端发的是远程图片地址，请求会被明确拒绝并说明原因，而不是把图片悄悄丢掉。

上下文长度与模型能力

新模型优先使用上游提供的上下文长度。没有长度时填入默认 32,768 tokens，并标注为待确认；可调整默认值，也可分别修改模型。

已保存模型和手动设置不会因为重新获取目录而被自动覆盖。需要更新已有模型时，显式采用上游长度。该长度用于容量检查、历史压缩与选择降级候选，不能把未知长度随意填大。

  1. 检查长度来源是上游提供、默认值、已保存还是手动设置。
  2. 结合官网或实际服务限制确认上下文；上下文总窗口不等于最大输出长度。
  3. 工具与视觉能力未知时先保持关闭，确认支持后再启用；流式能力也可单独调整。
  • 不同中转服务对同名模型可能施加不同窗口限制。Ollama 模型元数据也不一定等于服务器当前实际分配值。
  • Gemini 的 inputTokenLimit 是输入上限；不要将其理解为输出预算。

主用、优先级与自动降级

启用的供应商参与路由。主用供应商在满足能力、上下文、健康和限流要求时优先；卡片更多菜单可调整优先级、停用或复制配置。

客户端可以请求虚拟模型 auto，或使用 fastest、smartest、reliable、balanced 临时选择策略。也可以请求具体别名，或使用供应商:模型限定目标。含冒号的完整模型名会优先匹配，因此 :free 和 :latest 标签可以正常配置。

  1. 先给主用和备用供应商各配置至少一个需要的模型，并分别测试。
  2. 在供应商页选择路由策略，在设置中检查是否启用故障转移与候选尝试次数。
  3. 通过用量与审计核对真实路由和错误，避免只凭卡片名称判断请求使用了哪个模型。
  • 超时、408/409/429 和可重试 5xx 可在尚未开始流式输出时触发候选切换。401/403 鉴权失败不会跨供应商重试。
  • 已经开始输出的流式响应不能透明换家；中途断流会报告失败，避免重复输出或伪造成功。
  • 切换到更小窗口的模型前会重新检查容量；完整工具交换放不下时会明确报错。

接入 Codex / Claude Code：先备份配置

在设置的客户端接管区域选择 Claude Code 或 Codex，点击备份并写入配置。程序先为所有已有目标文件创建唯一备份、刷盘并逐字节核验，全部成功后才开始写入。

Codex 使用独立的 model_providers.llm_gateway、responses 协议和 auto 模型。Claude Code 使用本地网关地址及本地统一 Key。原有模型选择和配置字节内容会保存在备份中。

  1. 关闭准备接管的客户端，确认设置中的本地网关地址和统一 Key。
  2. 选择客户端并执行备份并写入配置。仔细阅读每个文件的处理结果和完整备份路径。
  3. 操作成功后重新启动对应客户端，发送一个简短请求验证。
  4. 需要恢复时先关闭客户端，另存当前配置，再将本次记录的备份复制回原路径。
  5. 写入客户端配置后，点「运行连通性自检」：它会检查网关健康接口，并用统一 Key 发一次最小请求，确认端到端真的可用（会消耗极少量 token）。
  • 已有配置无法解析或备份失败时，不会开始改写。首次创建文件没有原件，会明确标记为新建。
  • 多个文件不是跨文件事务；写入阶段发生部分失败时，错误会列出已验证的备份，供逐项恢复。
  • 备份可能含原客户端凭据，应留在可信本机位置。格式化后的文件可能不保留原注释，原注释仍在备份中。
  • 当前支持 Gemini 上游，但没有 Gemini 原生入站协议，因此 Gemini CLI 自动接管暂不可用。
  • 本机 CLI 的安装、检测与更新是独立能力，见「安装与更新本机 AI 编码 CLI」一章；接管写入只影响列出的客户端配置文件。

安装与更新本机 AI 编码 CLI

设置 → 本机 CLI 工具集中管理 21 个主流 AI 编码 CLI。检测只读取 PATH 与常见安装目录，不改动任何文件；安装与更新都会先展示确切命令，确认后才执行。未安装的工具同样会查询 npm 最新版本并显示「将安装的版本」，可以直接一键下载安装。

覆盖范围：Claude Code、Codex CLI、Gemini CLI、Qoder CLI（国际版/国内版）、OpenCode、OpenClaw、Pi Coding Agent、DeepSeek Harness、WorkBuddy、Cline、Amp、Auggie、Continue CLI、Crush、Factory Droid、iFlow CLI，以及以官方脚本安装的 Grok Build、Cursor CLI、TRAE CLI、Hermes Agent。

安装来源分两类，界面在状态列标出：npm 类通过 npm 全局安装，可查询 npm 最新版本并提示「可更新」；官方脚本类执行厂商提供的 PowerShell 安装脚本（仅 Windows 可用），脚本始终安装最新版，因此不比对版本，界面提供「安装 / 重新安装」。

  1. 点「检测本机 CLI」查看每个工具是否安装、实际路径与版本；该操作只读本机、不联网。
  2. 点「检测并检查更新」再查询 npm 最新版本：已安装工具据此提示「可更新」，未安装工具显示将安装的版本（官方脚本类不参与比对，最新列显示「以脚本为准」）。
  3. 未安装的工具点「安装」；已安装且查到新版本时点「更新」；已安装且已是最新或使用官方脚本时点「重新安装」——每个按钮都会把工具装到最新版。弹窗会展示将执行的确切命令，确认后才执行。
  4. 执行完成后界面会重新检测；若仍显示「未检测到」，请按安装输出检查 PATH，或在新开的终端中重试。
  • npm 类需要本机已安装 Node.js 与 npm；官方脚本类需要能访问厂商下载站点（如 x.ai、cursor.com、trae.cn）。前置条件不满足时按钮会禁用，并在表格上方说明原因。
  • 官方脚本会从厂商地址下载并执行安装程序，属于会改动本机环境的操作；执行前请核对弹窗中的命令与地址，确认来源可信。
  • 安装与更新只影响本机全局 CLI，不会修改网关配置、供应商或客户端接管配置。
  • 未安装的工具显示「未检测到」并给出安装入口，不会把未知状态显示成已安装；检测失败也不会推断出「已安装」或「没有配置」。
  • 工具清单与安装命令全部来自内置常量，不接受用户输入；清单更新随应用版本发布，不会在运行时从网络拉取。

桌宠与 AI 软件监控

设置 → 桌宠与 AI 监控可以开启一个独立的置顶小窗口：它用宠物包动画呈现网关与本机 AI 软件的任务状态。单击桌宠会打开主窗口并跳到用量与审计；按住约 0.16 秒后拖动可移动位置；右键打开系统原生的操作菜单（选择宠物 / 打开主窗口 / 暂停状态监控 / 隐藏桌宠）。

状态按最高优先级决定宠物动作：网关或任务出错 → 出错；网关有请求或检测到进行中的任务 → 工作中；其余为 空闲。任务状态来自工具自身的会话日志（当前支持 Qoder CLI：~/.qoder/logs/sessions 下最近 15 分钟内仍在写入的会话），能区分进行中 / 已完成 / 出错；网关状态单独标注，便于区分「网关出错」与「任务出错」。

同页按软件聚合列出本机正在运行的 AI 软件：编码 CLI（按受支持工具的可执行文件名匹配）与常见 AI 桌面应用（Qoder IDE、Cursor、TRAE、Windsurf、Claude Desktop、腾讯元宝），标注类型、进程数与内存合计；同一软件的多个进程（如 Electron 的主/渲染/GPU 进程）合并为一行。

宠物用下拉框选择（就在「开启桌宠」旁边），桌宠窗口会自动切换并记住；「大小」滑块可在开启后把桌宠调整到 50%–200%，同样会被记住。

  1. 先在「本机 CLI 工具」中确认需要的工具已安装；AI 编码 CLI 的进程监控复用同一份工具清单，桌面应用与任务日志走内置监控表。
  2. 点「开启桌宠」：出现置顶小窗（默认 0.6×，按上次保存的大小显示）。首次开启会自动选用第一个已安装的宠物。
  3. 用「宠物」下拉框切换宠物，用「大小」滑块调整（拖动后窗口立即变化）；也可在桌宠右键菜单里切换宠物或暂停监控。
  4. 拖动桌宠调整位置；单击它跳到用量页。
  5. 需要结束某个运行中的 AI 软件时，在卡片表格中点「结束」：确认弹窗会说明将结束的进程数，确认后终止该软件当前检测到的全部进程（含各子进程）。
  6. 安装新宠物：点「浏览 Petdex 商店」查看官方 CLI 的原始输出，把其中的 slug 填入输入框，点「从 Petdex 安装」并在确认弹窗中核对命令；安装成功后会自动设为当前宠物。
  • 宠物来自第三方 Petdex；本应用只读取 ~/.petdex/pets 下的宠物包（pet.json 与 spritesheet.webp/.png），不会修改或上传宠物素材，也不会把商店内容当作本应用的内置资源。
  • 安装宠物通过官方 Petdex CLI（npx --yes petdex@latest install <slug>）执行，属于会联网并写入用户目录的操作；slug 经过白名单校验后作为独立参数传递。
  • 结束进程会终止该软件当前检测到的全部进程与子进程，未保存的工作可能丢失；结束 IDE 等同关闭该应用，确认前请核对软件名与进程数。
  • CLI 进程按可执行文件名匹配，通过包装脚本启动的进程可能匹配不到；桌面应用按进程名匹配（如 Qoder CN.exe、Cursor.exe），未列出名称的应用不会显示，也不会有误报。
  • 任务日志只读取、不修改；超过 15 分钟没有新写入的会话不再算作进行中的任务，避免过期任务驱动宠物动作。IDE 内的任务状态暂未纳入（其数据未提供可读的本地接口）。
  • 桌宠窗口不进入任务栏、始终置顶；点「隐藏桌宠」或关闭它会销毁窗口，重新开启即可恢复，位置与大小由系统记忆。

手动接入其他客户端与请求示例

OpenAI 兼容客户端通常填写基础地址 http://127.0.0.1:15721/v1、本地统一 Key，以及模型 auto 或已配置的别名。Responses 入口是 /v1/responses；Anthropic 入口是 /v1/messages；Ollama 兼容聊天入口是 /api/chat。

先用免鉴权的 /healthz 判断本地 HTTP 服务是否启动，再测试实际聊天。健康检查成功并不证明上游模型已经可用。下面的 PowerShell 示例会提示输入本地统一 Key，并为这段会话生成独立 user 值。

Invoke-RestMethod 'http://127.0.0.1:15721/healthz'
$secureKey = Read-Host '输入设置页中的本地统一 Key' -AsSecureString
$headers = @{ Authorization = 'Bearer ' + [System.Net.NetworkCredential]::new('', $secureKey).Password }
$conversationId = 'manual-' + [guid]::NewGuid().ToString('N')
$body = @{ model = 'auto'; user = $conversationId; messages = @(@{ role = 'user'; content = '你好，请简短回答。' }) } | ConvertTo-Json -Depth 8
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:15721/v1/chat/completions' -Headers $headers -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
  • 地址与端口被修改后，示例中的地址也要相应调整。不要给客户端填上游供应商 Key。
  • 同一段会话的后续请求复用 $conversationId；新建独立会话时生成新值。不要让所有聊天共用一个 user。

会话续接与上下文阅读

网关将会话保存到本机 SQLite。客户端回传响应中的 X-Session-Id，或使用每段会话唯一且稳定的 user，即可恢复既有上下文。没有标识的首请求会生成独立匿名会话；后续不回传标识会被视作新会话。

会话上下文页可按标题、模型、供应商或会话 ID 搜索。详情显示消息数、累计 token、粘性路由、摘要和消息时间线，工具调用与结果可关联查看。

  1. 在客户端完成一次请求，然后刷新会话列表。
  2. 选中会话，检查实际路由、模型、摘要和最新消息。
  3. 长摘要可在摘要区域内滚动；工具调用记录可展开，长文本会自动换行。
  4. 仅在确定不再需要时删除会话。删除是实际删除本地会话数据，引导和手册不会替你执行。
  • 宽窗口两栏显示，较窄窗口上下排列。快速切换会话不会被晚返回的旧请求覆盖。
  • 应用重启后可继续读取持久化上下文，但客户端仍需使用正确的会话标识。

自动与手动压缩上下文

当摘要与未压缩历史的合计预算达到设置中的阈值时，网关会压缩较早历史并保留近期内容。会话详情也提供压缩上下文按钮。工具调用与对应结果作为完整交换保留。

自动摘要失败时，会使用保留必要近期内容的策略；内容仍无法容纳时返回明确错误。压缩后重放旧历史会去重，避免重复追加。

  1. 在设置中查看压缩阈值和保留近期消息数量，结合模型上下文窗口调整。
  2. 在会话详情查看压缩次数、摘要和已压缩标记。
  3. 确需主动缩短历史时点击压缩上下文，等待结果更新后再继续操作。
  • 摘要是一种信息压缩，不能保证逐字保留原始消息。重要的持久任务约束应让客户端清晰表达。
  • 上下文持久化与请求审计是不同数据：即使用量审计没有保存完整请求体，会话页仍会显示为续接而保存的消息。

查询额度、订阅与剩余时间

在供应商卡片的更多操作中选择查询额度 / 有效期。打开时查询一次，可手动刷新或切换适配器。所有请求使用该供应商保存的 Key 和原服务地址。

OpenRouter 显示 Key 消费限额及 Key 有效期；DeepSeek 显示账户余额；New API 兼容服务显示 Key 原始额度；Sub2API 兼容服务按实际响应显示 Key 窗口、钱包余额、订阅周期和订阅到期。

  1. 先阅读每张数据卡的账户、Key、模型或订阅范围标记。
  2. 查看已用、总量、剩余以及明确提供的重置时间。
  3. 订阅到期和 Key 到期分别查看，界面根据返回的日期计算剩余天数/小时。
  4. 自动识别失败时，可在确认服务兼容协议后切换适配方式，或到服务官网控制台查询。
  • 未提供不等于 0；Key 未设消费上限不等于账户余额无限。
  • 模型已用费用不能推算免费模型剩余调用次数。SenseNova、智谱等当前未适配的官网余额，会明确提示查看控制台。
  • 本轮 OpenRouter 额度实网查询成功；Air Outer 没有返回已识别的数据，不能保证其订阅剩余时间可获取。
  • 查询错误会清除旧读数，不会拿过期余额继续显示，也不会据此自动停用供应商。

用量与审计：排查实际请求

用量与审计用于查看请求结果、耗时、token 以及实际路由。它反映网关本地记录，与供应商官网账单的结算周期或统计口径可能不同。

当客户端报错或疑似发生降级时，先核对请求状态、所用供应商和模型，再检查上游返回类型。不要仅凭本地用量推算官网剩余余额。

  1. 在客户端发送可区分的简短问题。
  2. 打开用量与审计并刷新，核对对应请求的结果和路由。
  3. 结合供应商测试连接和额度查询确定是本地鉴权、网络、上游权限还是容量问题。
  4. 在「供应商」页点「刷新定价」可从公开定价源获取最新单价；结果会说明更新了几个、跳过几个手工定价、哪些模型未在定价源中找到。
  5. 在「用量与审计」页查看分币种花费、近 30 天按供应商/模型的花费，以及每次请求命中的计价档位（例如「谷时 · 输入≥272K 档」）。
  6. 同一页的「Token 计数校准」表显示每个模型「上游实际 / 本地估算」的比值；样本积累后，上下文预算与自动压缩会按这个口径换算。可随时「重置校准」。
  • 本地用量审计与会话消息存储分别管理。会话续接需要保存消息，分享日志或数据备份前请核对其中的内容。
  • 花费是本地估算：按你配置的价格 × 实际 token 计算，不是上游账单。未配置价格的模型只统计 token，显示为「未计价」，不会折算成 0。
  • 自动获取定价只更新「目录定价」的模型；手工填写的价格永远以你填的为准。厂商直连的 Provider 只接受完整模型 ID 精确匹配，避免把中转目录的价格套用到官方账户上。

项目快照与本机数据备份

设置中的项目快照保存供应商、模型映射、路由及运行配置，适合在不同工作配置间切换。应用快照会替换当前这些配置，并按相同供应商 ID 保留本机 Key。

快照不是完整灾备，不等于备份会话数据库和加密主密钥。Windows 默认应用数据目录是 %LOCALAPPDATA%\llm-gateway，包含 config.toml、gateway.db、master.key 和运行日志。

  1. 切换重要配置前，为当前状态命名并保存项目快照。
  2. 应用快照前阅读替换提示，应用后按页面要求重启需要重启的配置。
  3. 备份完整本机数据时先从托盘退出网关，再备份整个应用数据目录，并妥善保护副本。
  • Windows 主密钥使用当前用户 DPAPI 保护，直接复制文件到其他 Windows 用户或另一台电脑不保证可以解密。跨机器恢复需要预先规划可恢复的主密钥，不能只复制 gateway.db。
  • 客户端接管备份位于客户端配置旁边，与项目快照和网关数据备份是三种不同机制。

网络设置、局域网与远程访问

日常在本机使用时保持默认回环监听。只有需要其他设备接入时，再在设置中配置局域网访问或远程 HTTPS 反向代理，并按页面提示重启。

远程模式使用独立访问 Key 和会话命名空间，按客户端设置限流。管理界面仍在本机使用；不要把本地统一 Key 当作所有远程客户端共用的凭据。

  1. 先确保本机请求和上游连接可用，再配置远程访问。
  2. 为每个远程客户端创建独立 Key，保存创建时显示的值；按实际需要配置 HTTPS 公网地址。
  3. 检查设置返回的重启提示，重启后从目标设备验证访问。
  • 本版本未完成真实公网域名 TLS 部署验收；详细边界见设计方案和验证记录。
  • HTTP 代理设置影响上游访问。模型目录和额度查询也使用网关的代理配置。

常见问题与排查顺序

连不上本地网关：确认程序未从托盘退出，检查端口和地址，先访问 /healthz。地址被占用时，避免重复打开多个网关进程。

模型目录读取失败：核对协议、API 地址和 Key；完整 Gemini 调用 URL 需要改成 API 根地址。服务没有目录接口时，使用手动配置并测试。

401/403：核对客户端使用的是本地统一 Key、上游使用的是供应商 Key，并检查上游账户权限。429：核对调用限额和是否配置可用备用供应商。

上下文超限：核对模型实际窗口，检查是否保留了过大的单个消息或工具交换。长会话可压缩，但不应通过虚报模型窗口来绕过限制。

接管失败：阅读具体目标和备份路径。原文件格式错误时先修复原配置，再重试；备份失败不要直接覆盖原件。

额度显示未提供或不支持：服务可能没有适配接口、Key 权限不足或部署版本不同。请到对应官网控制台确认，不能将缺失值解释为额度耗尽。

  1. 记录出现问题的页面、操作时间和错误类型，隐藏所有 Key 后再分享诊断信息。
  2. 先检查本地服务，再检查供应商连接，最后核对客户端模型名与会话标识。
  3. 需要核对本版本测试和安装包时，查看 docs/0.1.1验证记录.md；开发和协议细节见 README.md 及设计文档。
