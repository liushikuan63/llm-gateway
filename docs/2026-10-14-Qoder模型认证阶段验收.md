# Qoder 模型认证阶段验收

本阶段继续 R5.5/R5.6。模型 jobToken 与设备登录独立处理，复用既有加密 app_secrets 和 HTTP 客户端，不增加依赖、数据库表或本地 HTTP 翻译服务。此阶段不等于模型推理已实现或真实平台接受认证。

## 实现与边界

- Global/CN 使用各自固定的 openapi 域名。签发 POST `/api/v1/me/jobToken` 使用设备 Bearer 与公共 clientId；刷新 POST `/api/v1/jobToken/refresh` 只传模型 refresh_token，不传设备 Bearer。
- 模型有效期按当前公开程序的独立毫秒合同解析；未知有效期为 null，不猜默认期限。设备登录的相对秒数解析保留。模型 pair 按区域、用途及设备身份/组织/本软件安装ID/access代次绑定。
- 网络之前持久化单次预约；同代失败或未知结果不重放。独立服务通过数据库CAS竞争，取消留下墓碑，迟到结果不得复活模型认证。失败保留旧加密 pair。
- 显式模型刷新不自动轮换仍有效的临期设备认证。模型准备操作可续设备，成功后按新代签发；设备认证真正过期时必须先完成有效设备认证，不能跳过身份核验。
- 新增 `qoder_job_status/prepare/refresh/cancel` IPC 与 `--qoder-job-status/prepare/refresh/cancel` 后台命令，选择器为 `global:本机账号` 或 `cn:本机账号`，沿既有 `--data-dir` 规则。DTO只返回状态、到期、刷新可用性和预约阻断；`inference_verified` 固定 false，秘密不返回前端、命令行或日志。
