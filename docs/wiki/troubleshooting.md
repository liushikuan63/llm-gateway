# 故障排查

## WorkBuddy HTTP400 / 11128

当前已知用户触发是“聊天测试”选择 WorkBuddy 国际版的 DeepSeek 模型后返回 HTTP400。保存的日志曾观察到业务码 11128，但历史原始响应体未保留。**11128 单独不能证明唯一原因，当前不能称真实聊天已修复。**

检查顺序：确认所选为本区域独立账号供应商；核对本地保存状态及目录；检查安全错误分类和该次单独收据。需要真实请求时只能使用仍有效、未消费的对应单次授权，失败或未知不自动重试。不要反复重登、换模型、改 UA 或把别的平台旧授权当作新的许可。

只有上游同一权威错误对象明确声明 `11128 + request illegal`、且响应不反射本次凭据时，适配器才输出固定 `policy_denied` 诊断。未知 11128 不推断策略拒绝，自由错误体和内部请求 ID 不公开回显。认证在本地未到期不能证明云端权限；额度、目录和签到成功也不证明模型可调用。

## 503 与旧桥接

“桌面桥接”仍依赖对应客户端及本地桥接；独立网页登录不会自动把旧供应商迁移成直连。关闭桥接后选择旧供应商会失败。选择正确的独立账号模型，不为测试擅自启动 WorkBuddy/Trae 或重新开启其自启。

## HTTP200 但提示空回复

后续候选区分正文、推理和 `refusal`，见[请求流程](request-flows.md)。这是桌面成功响应消费者的独立缺口，不能解释 HTTP400。修复状态需看对应候选的包与安装证据，M0 安装版并不包含这一修复。

## 搜索失败或部分成功

空页、挑战页、超时、无法解析和来源全部失败分别保留边界。某源失败不应掩盖另一源成功；有 Key 后端 401/403 不回落免费源。新聚合尚未最终安装时，内核通过不等于用户入口已可用。固定诊断可反馈，完整查询、自由错误体和凭据不写入公开报告。

## 维护反馈

记录时间、地区、供应商/模型、HTTP/安全业务码和对应阶段证据即可。不要粘贴密码、Token、Cookie、master key、完整配置或第三方凭据文件。遇执行额度上限记录原错误并停止，不换模型或执行器绕过。
