# 客户端 V2 意向账本

V2 为受管客户端的派发意向提供可保留的 SQLite 记录。刚登记的意向表示发送结果未知。审计关联只接到已存在的请求。当前迁移不会把已有审计、日用量或旧客户端记录当成 V2 证据，也不会因为旧请求过期而清除意向。账本不设总数门禁或自动清理。

启动时先在一个读取快照中检查任何已有 V2 结构和数据。如果发现缺损、不符合合同的结构，或只有大小写不同的同名对象，启动会在旧表迁移前返回错误。结构比较只归并 SQLite 识别的空白字符。标识符中的其他字符保留原样，以免把不同结构误认为相同。对于尚未建账本的库，完成原有迁移后在一个写事务内新建三张表、两个索引和十二个触发器，初始化库标识并复核结构与行。重复打开时保留同一个库标识。降级前请关闭所有写入者并单独保留原库及 WAL 一致备份。不要通过删除 V2 表来修复启动错误。

已知未发送仅适用于明确被配额或并发门禁拒绝的代理意向。存储层的待核阅选择由持有写入权的运行时捕获，核阅时同时比对库身份、条目世代和修订。删后重插、相同值更新或重开池都不能复用旧确认。批量核阅全成或全退，核阅不删除记录、不确认用量或账单。

在 NativeExact 路径，先通过本地请求和账号校验，再提交一条独立的派发意向。提交之后重新检查配置、免费策略和截止时间，才允许同一个原生 POST 开始。账本无法确认意向提交时，不发 POST。取消或超时后，不能根据观察到零次 POST 将记录改成「已知未发送」。

派发时捕获的库和意向由原请求的审计持有，正常结束或取消后，审计、日用量和意向关联在同一个写事务中完成。提交前强制退出可留下未关联意向；提交后重开可看到关联和当时已知的用量。输出、总量及成本缺乏证据时保持未知。没有创建意向的早期拒绝仍沿用普通审计。

本分支的生产接线限于 NativeExact。其他派发类型、Stats 与导出消费者以及真实账户、正式数据库、掉电和实体安装分别验收。运行回归的方法见[开发与验证](development.md)。
