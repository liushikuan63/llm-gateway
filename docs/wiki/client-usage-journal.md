# 客户端 V2 意向账本

V2 为受管客户端的派发意向提供可保留的 SQLite 记录。刚登记的意向表示发送结果未知。审计关联只接到已存在的请求。当前迁移不会把已有审计、日用量或旧客户端记录当成 V2 证据，也不会因为旧请求过期而清除意向。账本不设总数门禁或自动清理。

启动时先在一个读取快照中检查任何已有 V2 结构和数据。如果发现缺损、不符合合同的结构，或只有大小写不同的同名对象，启动会在旧表迁移前返回错误。结构比较只归并 SQLite 识别的空白字符。标识符中的其他字符保留原样，以免把不同结构误认为相同。对于尚未建账本的库，完成原有迁移后在一个写事务内新建三张表、两个索引和十二个触发器，初始化库标识并复核结构与行。重复打开时保留同一个库标识。降级前请关闭所有写入者并单独保留原库及 WAL 一致备份。不要通过删除 V2 表来修复启动错误。

已知未发送仅适用于明确被配额或并发门禁拒绝的代理意向。存储层的待核阅选择由持有写入权的运行时捕获，核阅时同时比对库身份、条目世代和修订。删后重插、相同值更新或重开池都不能复用旧确认。批量核阅全成或全退，核阅不删除记录、不确认用量或账单。

在 NativeExact 路径，先通过本地请求和账号校验，再提交一条独立的派发意向。提交之后重新检查配置、免费策略和截止时间，才允许同一个原生 POST 开始。账本无法确认意向提交时，不发 POST。取消或超时后，不能根据观察到零次 POST 将记录改成「已知未发送」。

派发时捕获的库和意向由原请求的审计持有，正常结束或取消后，审计、日用量和意向关联在同一个写事务中完成。提交前强制退出可留下未关联意向；提交后重开可看到关联和当时已知的用量。输出、总量及成本缺乏证据时保持未知。没有创建意向的早期拒绝仍沿用普通审计。

本分支的派发接线限于 NativeExact。其他派发类型、真实账户、正式数据库、掉电和实体安装分别验收。运行回归的方法见[开发与验证](development.md)。

## 桌面核阅已知未发送记录

「用量与审计」的核阅列表由用户手动读取。列表按 attempt 标识分页，每页最多 50 条，查询独立意向账本，不使用当前审计筛选。只有尚未关联、尚未核阅且确定在配额或并发门禁被拒绝的 AgentIntent 可提交核阅。

每次只打开一条记录的原生确认窗口。运行时持有这次核阅的私有版本快照；网页只提交记录标识和请求标识，确认由原生窗口返回，随后存储层一次性检查版本并写入。取消、版本冲突或结果未知都不会自动重试。离开页面会请求取消；注册通知迟到时，再对同一请求发取消。旧页面的结果不会回填，新核阅要等上一次结束。核阅不会补记请求、用量或费用。

## 用量、审计与原始导出

「用量与审计」通过 `stats_overview_v2` 读取最近 24 小时的概览，通过 `query_requests_v2` 读取当前筛选的审计页，通过 `usage_stats_v2` 读取同一筛选的完整用量覆盖。V2 概览不含 V1 的 token 数字字段；证据不齐时返回已知小计与未知请求数，可靠合计为空。请求次数和本地日聚合花费沿用各自口径。用量覆盖读取失败时，仍可显示本次筛选成功读到的审计和人工反馈；上次完整概览会标为可能过期。派发意向按意向创建时间独立统计，不增加审计请求或花费；只有版本存在、未关联请求或后台任务且明确被配额或并发门禁拒绝的代理意向才计入已知未发送。

「最近请求」的横向滚动只作用于表格，筛选、导出、页码和当前用量摘要留在外层。Tab 可进入具名表格区，键盘可横向浏览并用同一行按钮开关明细；长调用方、模型名和路由在单元格内换行，保留完整文本。

审计读取逐条标明正文可读、缺失或省略。正文读取限制为每条 256 KiB、一次合计 8 MiB；省略及损坏不会从请求计数中消失，也不会变成零用量。`export_requests_v2` 按点击时的完整筛选导出，不使用当前页的偏移或大小。存在超限、不可解码、无法解析或不符合解析限制的正文时，返回 `审计原始导出包含超限或不可读取正文，请缩小筛选范围后重试`，并保留已有文件和 CSV 列说明。SQL `NULL` 正文仍按缺失处理，有效的空数组仍可导出。成功导出的 JSONL、CSV 和列说明保持原格式，V1 命令及返回字段仍可使用。
