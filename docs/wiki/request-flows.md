## 桌面聊天、拒绝与持久历史

逐请求取消沿同一生产链工作：页面每次显式发送生成新的 UUID；IPC 以调用窗口和 UUID 注册有界进程内控制项，发送就绪通知后页面才启用「取消当前请求」。就绪 Channel 在进入命令时立即取得 RAII 所有权，验证、网关关闭或注册失败也会发送 end 清理回调；未收到就绪通知不能沿用旧请求的可取消状态。旧的无控制参数调用兼容保留。

取消只丢弃目标请求的 HTTP future，不关闭网关、不取消其他请求、不自动重试，也不推断额度退款。派发前已排队的取消不轮询发送 future；响应与取消同时就绪时保留已知响应结果。取消命令返回 accepted 只表示信号已接收，页面仍等待请求终态；成功结果必须清理等待取消提示。确认取消后保留草稿并恢复输入焦点；已派发的取消审计沿 S2 路径持久化为 499/`client_cancelled`，上游可能仍有消耗。调用方 UUID 的无连字符形式只用于关联审计 trace，不包含凭据。

源码浏览器 IPC 替身验证按钮名称、键盘、禁用状态及完成竞态；Rust 自有 loopback 验证实际发送/499/200、并发和网关存活。新安装产物的真实 UI→IPC→取消及重启持久化须另由独立执行者验收，不能用浏览器替身或 `cfg(test)` 权益成功合同替代。

### N4 原生上游的流终态

Anthropic 的 `message_delta` 只更新结束原因和累计用量，独立的 `message_stop` 才确认流完成；事件顺序依据[官方流式协议](https://platform.claude.com/docs/en/build-with-claude/streaming)，本地夹具不是供应商抓包。[解析器](../../src-tauri/src/proxy/upstream.rs) 将前者投影为已有 `Finish`／`Usage`，后者仍为 `Done`，复用各出口已有结束原因与用量合并。缺少 stop 的 EOF 不再提前输出成功完成帧；沿原不完整流路径记录失败、保留部分正文且不更新成功粘性，不在正文后切换备用重放。正常结束、长度停止及工具结束原因不改含义。协议终态不是 VerifiedEntitlement 或供应商结算凭证，不新增收费单位或政策。

[实际 Gateway／自有 loopback 回归](../../src-tauri/tests/protocol_stream_boundaries.rs) 另覆盖 Gemini 的 finishReason 与 Ollama 的 done，各自对照完整／缺失终态；Anthropic 还覆盖 delta 后错误且无 stop。每个变体使用独立数据库／健康状态，启用备用目标但只允许一个显式 POST；停止网关后按权威 trace SQL 核对单审计、单尝试、200／502、已知用量、粘性和持久化正文。内部变体不另算顶层测试数。delta 后错误用例验证不误报成功，未声称各厂商内联错误码均已精确映射。该终态阶段没有验证TCP reset／代理热切换／升级版本或实装；后续自有出口／TLS矩阵见下文，N4整卡继续。

原生 OpenAI／Anthropic／Gemini／Ollama 的顶层非 NULL `error` 或 SSE `event: error` 现在会产生固定诊断的 502／`NoReplay`，并结束该解析流；正文后的错误不能再被后续完成标记掩盖。HTTP 请求已实际发出，内联错误本身没有证明零消耗或退款，因此正文前也不能自动重发／切备用。这是沿用已派发未知结果的保护边界，不改价格、免费资格、单位或结算政策；502 是网关的错误映射，不冒充上游原始 HTTP 状态。任意厂商 message 不进入返回错误或审计，`error:null` 与嵌套业务字段不触发该规则。非成功 HTTP 状态路径不变；Responses 显式错误的后续修补见下文。

[Ollama 官方错误说明](https://github.com/ollama/ollama/blob/main/docs/api/errors.mdx) 明确区分流内 error 对象与 HTTP 状态；本批四协议仍只使用人工 loopback 合同，Gemini error envelope 不是实时上游观察。回归通过真实 Gateway 证明首正文前单次派发／单审计／单尝试、正文后保留部分输出且不成功、不反射自有私密标记；当前错误种类只作通用失败，不把厂商 code／message 升级为收费凭据。真实版本、其他错误形状与整卡网络故障矩阵继续未验。

Responses 的 `response.failed`／`error` 也沿用同一已派发未知保护：旧 Gateway 首正文前确实触发第二次 POST，现以固定 502／`NoReplay` 拒绝重放。直接解析器原先仍携带任意上游 model／message，现不再保留它们；实际目标由可信的分派／尝试元数据归属，不能借错误载荷伪造。既有正文后失败保护本来通过，本批保留该正向事实，不冒充新修复。正常完成、原生 SSE 的工具参数装配以及合法 `response.incomplete` 的 length／usage 终态均保留；未把所有 incomplete 当失败。新增 Gateway 正常／前后正文错误和直接解析器均用自有 fixture，其他畸形或自相矛盾的终态、真实版本及实装继续未验。

流式 `response.completed`／`response.incomplete` 现还校验根包络：response 必须是对象、status 与事件一致、output 必须是带非空 type 的对象数组、不能同时含非 NULL error；completed 不携带 incomplete_details，incomplete 必须有非空 reason。声明的 response.*／error SSE 事件名若与 JSON type 冲突也拒绝。缺失／NULL／错误形状、失败或进行中状态伪装完成，以及矛盾详情均为固定 502／`NoReplay`，正文后不伪造成功，缺失 response 不再报内部协议错误。合法空 output、未知附加字段、普通完成／工具与合法长度结束仍有正控；这不是完整嵌套输出项 schema 校验或真实供应商验证。

仅在流式解析事件层，主用量字段缺失、NULL、部分缺失、溢出或 total 自相矛盾时保留 `usage: None`，不把它们补为已知零；完整已知零仍为 `Some(0)`，输入／输出已知且缺 total 时沿既有和数。非流式转换器和普通线协议的既有标量兼容格式保持原字节，不能据此宣称安装版用量 UI 已验或任意供应商的结算可信。16 种畸形包络分别经正文前／后真实自有 Gateway 读回审计／尝试／无重放；内部变体不累加顶层数量。更深的工具／输出语义、其他网络与版本及实装仍保留。

## 标准缓冲响应的参考计价依据

### N3 本机参考价预占

仅原预算开关开启且已鉴权远程 Key 的限额大于0时，[预算消费者](../../src-tauri/src/budget/holds.rs)为后台UUID／call ordinal建立[budget_holds旁表](../../src-tauri/src/db/budget_schema.rs)记录。最终标准HTTP body和override形成后，按所选模型配置的context上限、明确最大输出、全部分档／缓存单价／时段倍率计算保守参考预占，向上取micros；币种仍分开，不更改每百万token单位。输入上限是配置参考边界，不是供应商tokenizer或真实账单上界。未知价格、输出界、单位或旧未知消费拒绝受限调用；预算0、关闭与本机统一Key保留原路径。

`BEGIN IMMEDIATE` 内累计旧已知账与新预占／已知消费并建立唯一占用；最终发送前复核Key代次／限额／币种／白名单及目标。预算等待后重走原免费守卫，并在所有等待后做内存最终复核，不降低FreeOnly、不从手工零价生成免费资格。明确未进入send的错误可释放；持久派发边界后取消、超时、断连或不完整报告保留全额，不TTL退款、不自动重放或收费回退。同一请求尚有未知调用时不进入下一次模型调用。

完整buffered报告或有界raw stream报告加协议终态才可单次结算为已知参考费用；缺省0、先前完整报告后出现的不可解析数据、CLI退出0或回复文本均不替代完整依据。不能完整判断的stream（含部分拆分计数合同）保持未知占用，正常文字可交付。实际报告超预占如实记入并阻止后续，不裁剪费用，也不声称已阻止供应商实际超支。

准入UTC月固定，跨月完成归原周期，重启不清未确认占用。父审计／usage与占用关联沿[原事务](../../src-tauri/src/db/repo.rs)提交，关联行不重复累计；无预算派发的缓存命中／本地拒绝有明确零派发marker。删除审计只置空关联，不删除预算账；旧NULL费用不回填0。账号／CLI、Jev、refine及typed独立调用缺适用参考上界合同的受限调用失败关闭；可选分类／改写维持原本地降级，付费／自定义搜索缺合同不出站，detached压缩不借用受限请求预算。不限路径兼容另测；这不等于包含所有第三方费用的总账。

[自有Gateway／loopback回归](../../src-tauri/tests/support/budget_holds.rs)核对实际POST、buffered／stream、并发、取消、未知、存储失败、缓存、审计保留与普通兼容；模块内另核对最终等待竞态、单次结算、唯一约束、隔离文件库重开和UTC月。首红、夹具错误及实际门禁终态均沿第6轮`n3-budget-policy-v1`保留，不累加旧阶段通过数；前端未改，不冒充UI或安装验收。更多子请求计价合同及完整M0–M5继续按队列；现有设置页已有下述只读占用观察，未知人工处置仍须另有明确政策。

### N3 已批准的当月旧预算审计保留例外（源码／隔离验收）

先前待决策段落保留当时状态；用户现已明确批准原方案A及其正文／人工反馈保留影响。原purge_old_requests截止时间不变，单条DELETE只排除同时满足以下条件的旧行：access_key_id非NULL、ts在本次清理时刻的UTC自然月内、没有budget_holds.audit_request_id关联。其余行，包括本机、上月和已关联独立账本的审计，继续按原保留期清理；FK仍按原SET NULL／CASCADE处理。无新表／列、金额／币种换算／rounding、退款或重放政策。

原因是无账本的旧审计仍是当月参考消费的唯一依据：已知消费不能被清理洗成0，未知旧费用不能因删除变成已知0并开放预算。新账本已关联行删除后，独立账本仍保留参考消费／未定占用，不需要保留正文来重复计费。所有旧远程行按精确批准谓词处理，不额外按当前Key限额、币种、启用开关或费用是否为0缩放保留范围。

这是明确的审计保留期例外：符合条件的既有refined_prompt及关联人工反馈可能长于设置的1／7日保留期，直到当前UTC月结束并在后续清理中恢复原规则，最长约31日；不启用新的正文保存，不修改内容，不无限保留。周期按UTC自然月计算，跨年／闰月不按固定30日猜算。期满删除旧月依据不意味着未知消费被结算或退款；本片不制造0金额账本或供应商费用证明。
