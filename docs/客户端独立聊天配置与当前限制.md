# 客户端独立聊天：配置指引与当前限制



核验日期：2026-10-18。初次诊断依据安装 EXE ecb54166、本网关正式资料的只读元数据、本机登录/模型认证状态，以及用户在“聊天测试”页实际得到的 WorkBuddy HTTP400；后续补充两区 Qoder 官方目录与新版行为，实际安装状态以交付收据为准。没有代用户发起新模型请求。



## 先分清三种入口



- 名称含“桌面桥接”：依赖对应客户端与本机桥接进程已启动。网页登录不会自动启动它们，也不会把这条旧供应商变成直连。当前这三条旧供应商仍启用，对应 Qoder 127.0.0.1:8790、WorkBuddy :8791、Trae :8792；服务关闭时发送会失败。

- 名称含“本机 CLI”：通过本机命令执行，与独立网页登录/原生 HTTP 是不同路径。

- 独立账号供应商：在“客户端接入”中完成对应区域的网页登录、模型认证（如有）和“接入账号模型”，才会登记到供应商与聊天下拉框。登录成功不等于已经接入可调用模型。



## Qoder 国际版与 CN：官方模型名称与自动恢复



两区“本机账号名称”均为 `qoder`，不要把权益领取配置里的 `qoder_cn` 当作这里的本机登录名。最初诊断时模型认证已过期且尚未登记独立供应商；此后用户已更新认证并完成登记。2026-10-18追加的两区目录各一次只读核验显示认证已准备，国际版17项、CN版14项。目录可读仍不等于已验证真实聊天。



以后新增账号或需要兜底重新授权时，两区分别操作：



1. 打开左侧“客户端接入”，找到“Qoder 国际版”或“Qoder CN”网页登录区域。

2. 本机账号名称保持 `qoder`，点“检查登录状态”。

3. 旧安装版若提示模型刷新凭据过期，需要重新网页登录；无需删除原配置。新版会在模型使用前按需自动恢复：设备仍明确有效、已核验主体、旧模型认证明确过期且没有可用刷新凭据时，只签发一次新的模型认证，并核对主体。失败或结果未知会保留状态并停止同一轮重复签发，手动恢复仅作兜底；不会重放已发出的模型请求。设备本身失效或身份不明时仍需要用户重新授权。

4. 点“准备模型认证”，等待显示模型认证已准备并核验身份；再点“接入账号模型”。这两步不是生成模型回复。

5. 到“供应商”页确认出现相应区域的独立账号供应商，再到“聊天测试”明确选择它的一个模型。确认所选名称不是“桌面桥接”或“本机 CLI”。真实发送会按账号规则使用额度。



当前不应反复尝试恢复或直接删除加密记录。新版显示名称改进把 `qfmodel` 等内部编号展示为官方名称，同时保留调用ID和自定义别名。已登记账号有分区日期快照作为后备，新读取并登记的官方目录名称优先。例如国际版 `mmodel` 为 MiniMax-M3，CN为 MiniMax-M2.7；Auto、Sonus和Cantus等保留官方名称，不猜测底层模型。若仍运行旧版，界面仍可能显示旧编号，需要退出旧进程并更新。



## WorkBuddy：已配置直连，HTTP400不是简单缺Key



国际版、CN的本机账号名均为 `workbuddy`，本地登录状态均未到期；正式资料已有“WorkBuddy · workbuddy”和“WorkBuddy CN · workbuddy”独立供应商，分别27和18模型。选择这些独立条目，而非旧“WorkBuddy 桌面桥接”。独立账号型供应商不需要再填写普通API Key。



用户最初在聊天测试页选国际版 DeepSeek 时，实际日志为 HTTP400 / 平台业务码11128。历史响应未保存原始消息，不能仅凭业务码断言唯一根因。新版已保留安全业务码提示，并仅在上游精确声明 request illegal 时增加固定策略拒绝诊断，不回显自由响应消息或内部请求ID，不自动重放。当前不能引导用户反复重登或调整API Key。真实聊天仍需按单次授权独立验证；登录、目录和本批签到状态读取成功均不能替代真实模型结果。



新版还为 WorkBuddy 国际版与中国版提供独立的签到状态卡：在“账号权益”启用总开关，确认对应区域的本机账号名称（本机两区均为 `workbuddy`），再点“读取签到状态”。正常查询会先按需准备本网关保存的认证，失败或结果未知时停止该次自动重放；重新网页登录仍作为兜底。切换账号或关闭总开关会清除旧显示，后台已经发出的只读操作不会因此撤回。



状态卡区分未知字段与零积分，不把活动累计积分当作余额或模型权限。两区独立签到已提供账号关联、手动领取和独立每日时间：添加不同权益账号 ID，在对应账号卡片关联本区域独立登录，再明确启用账号及自动领取。新建 WorkBuddy 账号默认停用；原 Qoder/Trae 账号与定时配置保持。单次收据保留，未知结果不自动重发。

本轮新增“读取可用额度”：个人账号查询汇总、付费和免费赠送三来源，企业账号查询分配额度；不限量、零和来源不完整分别处理。总量来自平台汇总，资源明细不能冒充原子对账，付费标记也不能证明某个模型有调用权限。查询不发模型或领取请求，不在挂载时自动请求。本轮额度功能已完成源码、离线 HTTP/浏览器夹具、实际静默安装及原生总开关门禁验收；真实平台个人/企业额度和本轮认证自动刷新尚未核验，不能把本地门禁通过当作云端额度成功。



## Trae：当前独立聊天仍未完成真实验证



正式供应商中目前只有旧“Trae CN 桌面桥接”，没有完成登记的原生 Trae 供应商。原生目录选择冲突仍在继续定位，独立聊天不是填一个Key或改选模型即可保证成功。签到与聊天使用不同能力链，今日签到成功不代表模型调用成功。若主动使用旧桥接，需要用户自行启动客户端与桥接；本轮不会为测试自动重新打开这些窗口。



## 如何反馈有用的故障信息



记录所选供应商完整名称、区域、模型、错误码和发生时间即可。不要发送访问令牌、刷新令牌、主密钥或完整凭据文件。涉及真实模型验证时，按单次授权、无自动重试分别记录，安装/目录/夹具通过不等于聊天通过。
