# VibeCoding：代理独立开关与托盘

2026-10-15 用户明确要求：软件可选择是否开启代理，托盘直接操作，打开软件不能无条件强制代理；已确认 LLM 网关服务与系统网络代理两者都需要独立开关。

## 修改前生产路径

- `src-tauri/src/lib.rs` 初始化后无条件 spawn `proxy::server::serve`。托盘菜单只有打开控制面板/退出，没有代理切换。
- `src-tauri/src/proxy/server.rs` 拥有 listener snapshot 及取消时清理，但没有可复用的启停控制器。API 路由/鉴权、预算、审计及直接 `serve()` 行为已存在，不应重新实现。
- Mihomo/Xray 管理器与网关出站代理配置已有；外部 VPN 状态当前只读。尚无 Windows 系统网络代理设置的统一开关，不能把 LLM API 监听端口当作通用网络代理地址。
- 用户再次要求关闭 WorkBuddy/Trae 自启和进程。已发现执行环境 HKCU 视图与实际用户启动注册表不一致，五项从实际用户注册表移除，三个旧桥接端口及两类客户端进程归零。后续网络设置必须验证系统实际状态，不能只信执行环境或 setter 返回成功。

## 明确行为

1. **LLM 网关服务开关**：关闭时停止本软件拥有的监听，不接管或停止同端口外部服务；控制面板、日志、账号管理及定时领取仍可用。开启成功必须确实绑定监听；端口冲突/配置保存失败不能显示已启用。
2. **Windows 系统网络代理开关**：状态来自实际 Windows 连接设置，和 LLM 服务分别控制。手动开启使用已配置的通用代理地址或先前有效配置，不能把 15721 模型 API 地址写成系统代理。没有可用地址时说明原因。手动关闭/恢复必须处理静态代理、PAC/自动检测标志，并保存可恢复的原状态。
3. **启动选择**：新配置默认仅打开界面，不主动开启 LLM 监听，不写系统代理；提供明确的“随软件启动”选项，默认关闭。外部软件已设置的代理在启动时保持原样，只读显示来源/状态，不能偷偷关掉或改成本网关。
4. **托盘直接控制**：两项独立菜单，状态/忙碌/错误与界面一致，切换不打开主窗口、不抢焦点。无额外模型请求、收费探测或客户端启动。
5. 系统代理开关不等同于外部软件/TUN 的全部流量控制；已有 VPN 页的内核操作继续保持归属边界。不开关其他软件进程或第三方账号配置。
